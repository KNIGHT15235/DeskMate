## 在桌面安排事务

在持久工作区启动原有 `deskmate --work-dir <工作区>`。聊天支持保守的离线时间解析，例如：

- `明天晚上七点提醒我复习这份计划`
- `每周五下午六点，根据工作区的 project_notes.md 更新 outputs/weekly-summary.md`

解析本身不调用模型，不会立即保存或执行。任务窗口展示首次本地日期、时间、时区、星期、重复规则、工作区、材料文件、URL、输出与模型范围。确认后才保存。无日期、没有说明上午/下午的“七点”等表达会要求补充；任意自然语言、节假日规则及语音输入不在首版范围。也可直接打开“任务与执行记录”，用表单输入 ISO 本地时间，例如 `2026-11-21T19:00:00`。每周任务按首次日期的星期及本地时间重复。

“修改所选”载入定义，修改后重新预览、确认，新的定义只影响未来安排；已经开始的运行保留其旧范围。未开始的旧次队列取消，过去的执行快照和证据保留。“取消安排”停止未来周期，并取消未开始事项；该安排正在执行时也会请求取消，已经产生的文件副作用不会撤销。

提醒不会调用模型，到期变为“待处理”，在记录中点“完成这条提醒”。资料执行默认每次先“待确认模型调用”，点击“允许本次模型调用”后才进入执行。表单中可单独勾选允许该安排按指定模型周期调用；模型名称/型号和端点指纹随每次记录保存，配置变化要求编辑安排重新确认。时间确认本身不授予模型权限。

材料与输出是精确的工作区相对路径列表，URL 是精确的用户确认列表。可读取输出以满足 R4 覆盖前读取的要求。`ExecutionScope.check()` 在常规权限之前拒绝超出范围的工具或路径；范围内网页/写入仍遵循 R4 的 deny/allow/ask 规则，默认显示当次权限卡片。批准某次写入不会生成永久文件规则。网页、模型回答及工具均无创建个人周期授权的入口。调度运行不装配 Skills、MCP、Hook、记忆或摘要扩展。

定时运行也不自动加载工作区或用户目录的 `LIKECC.md`、`.likecc/LIKECC.md` 及其 `@include`。若任务确实需要工作区内的 `LIKECC.md`，须列入材料清单，作为普通文本读取，不展开 include。普通前台会话仍沿用原指令文件行为；模型范围内的材料限制不能只依赖工具调用检查。

## 运行、证据和存储

调用链：`ChatWindow / ScheduleWindow → DesktopController._schedule_command → ScheduleStore → _tick_schedules → _start_scheduled → SessionService.start → Agent → ExecutionScope / PermissionChecker / Interaction → RunEvent → _consume`。

Qt 主线程负责控件和普通数据快照。后台线程每 250ms 扫描，隐藏窗口不停止。真正退出首先停止领取，再取消、等待运行和资源关闭。前台忙时到期执行显示排队原因。定时执行使用自己的 Runtime 和持久 SessionService，与前台互斥；同一控制器只有一个活动 RunHandle、一个消费者。执行期间临时显示定时会话，结束后恢复原聊天快照，前台 SessionService 和输入草稿保留。历史中可以查看定时会话 ID，再用原会话恢复入口阅读日志；恢复不会执行工具。

| 文件 | 内容 |
| --- | --- |
| `<workspace>/.likecc/schedules.sqlite3` | `tasks` 定义、`executions` 单次执行快照及结果；`metadata` 保存所属工作区 |
| `<workspace>/.likecc/scheduler-lock.sqlite3` | 活动调度器持有的 SQLite 独占事务；进程死亡后 OS 释放锁，不用超时抢占 |
| `<workspace>/.likecc/sessions/` | 原 SessionService 会话及工具历史 |
| 用户确认的输出路径 | 实际 Markdown 成果；仍附来源账目 |

任务定义含稳定 ID、修订号、类型、内容、带时区的本地时间、一次/每周重复规则、下次 UTC 到期时刻和授权范围。执行记录含原定 UTC 到期时刻、冻结定义及修订号、状态、实际起止、原因、session/run、来源、成果、内容摘要与工具错误。对 `(task_id, due_at)` 建唯一约束；`scan()` 在 `BEGIN IMMEDIATE` 内插入并推进下一时刻；`start()` 通过带旧状态条件的 UPDATE 领取。重复扫描、重复确认和重复点击不会启动同一记录两次。

第二实例在取得所有权前不能进行恢复，活实例的运行状态保持原样。一个工作区首版只允许一个活动调度器；不要在网络盘上使用或同时跨 Windows/WSL 打开同一个库。本轮分别验证两种本地运行环境，未验证跨内核文件锁互操作。库绑定本机解析后的工作区路径，跨路径、跨 Windows/WSL 搬库不会悄悄复用授权，需要重新安排。

“运行结束”只说明 Agent 循环终结。“文件已写入”来自写入工具成功，“已回读核对”来自实际 ReadFile 的全文摘要一致。`MaterialsWorkflow.checkpoint()` 在写入前保存意图，在写入/回读后立即保存证据；`DesktopController._finish_scheduled()` 保存终态。写入被拒绝、工具失败、只有文字、取消等均保留实际来源、成果和错误，不将 `completed` 当成成果成功。写入前的意图只表明可能有副作用，不能当成成果已生成。

写入前检查拒绝不会生成新的副作用记录，也不覆盖此前已核对成果。真正进入文件写入边界后，I/O 错误可能已经截断或部分写入目标，保留 `write_unverified`、预期摘要及成果路径；未被后续全文回读核实的执行保存为“已中断，待核对”。下一周期在扫描和领取时均检查旧次结果，已经排队的周期也不能绕过核对。旧版 `write_failed` 无法证明没有副作用，重开时保守转为待核对并保留原 ID、证据、会话及起止信息。写入后报错但后续全文回读与预期摘要一致时，可凭该证据解除未知状态。

启动时 session/run 关联保存失败，会先取消尚未启动的模型运行，再保存中断线索、关闭资源并释放运行句柄；其他任务可继续调度。若恢复落盘或资源关闭仍失败，则保持错误状态和资源所有权，停止后续领取，等待重新打开工作区清理恢复。

## 退出与中断恢复

| 情况 | R5 行为 |
| --- | --- |
| 尚未到期 | 原定义继续等待 |
| 退出期间错过一次性提醒 | 重开后出现一条逾期待处理记录，可完成 |
| 周期错过多个时刻 | 合并为最近一次到期，记录合并数量，下一次移到未来；不逐次补跑模型 |
| 已领取但尚未执行 | 标为“已中断，待核对”，不自动重启 |
| 写入后终态未保存 | 保留 session/run、来源、写入意图和已提交证据，标为“已中断，待核对” |
| 旧次结果未知且又到下个周期 | “等待核对旧次结果”，不自动执行 |

查看旧次详情、会话日志和磁盘后，勾选“我已核对……”再点“明确发起新一次尝试”。这会创建关联 `retry_of` 的新记录，仍要求确认本次模型调用；不会修改旧次原定时刻、证据或重新播放旧工具调用。一个旧记录只产生一个直接重试，连续重试沿新记录继续。尚未开始的受阻周期合并到这次明确尝试。重试沿用旧次范围，扩大范围应编辑安排并重新确认。

首版时区限定为 `Asia/Shanghai`（2000 年以后的 UTC+08）和 `UTC`，不依赖 Windows 额外安装 tzdata，两平台语义一致。其他时区要求换算为 UTC，不猜测夏令时重复或不存在的本地时间，不承诺复杂日历语义。完全退出期间没有后台服务，因此不会准时弹出系统提醒；R7 再处理系统通知、静音和主动跟进。
