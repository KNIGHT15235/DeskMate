# R6：可确认、可追溯的工作区记忆

本轮在独立仓库 `main` / `6ea15eed1d6396912abc3a102b87f13963510015` 上实施。桌面默认启用本地工作区记忆，普通对话不自动变成已确认事实；主动通知、稍后提醒和继续处理仍留在 R7。实际自动化结果与人工覆盖边界见 [验证记录](verification.md#r6-独立仓库长期记忆2026-11-2223)。

## 保存与管理

在聊天中发送 `请记住，我的周报按结论、依据、行动项排列`，会直接打开待确认记忆，不为此调用模型。核对内容和类型，点击“确认保存”后才参与召回。这个简短入口只识别开头的“请记住/记住”；复杂的混合任务请分开发送。

“工作区记忆与来源”窗口也可点击“新内容”，填写用户偏好或项目事实，再“列为待确认”。资料任务结束后，填写需要记住的事务线索，点击“关联本次资料运行”，核对来源后确认。该按钮关联当前会话最近一次运行的实际证据；切换/恢复会话后不会自动重新生成待保存内容。

每次新运行开始时，上一轮的关联入口失效。若本次来源记录因数据库锁等错误保存失败，“关联本次资料运行”保持不可用；后续运行成功保存来源后恢复。后端还会核对来源的会话和运行 ID，不能把上一轮资料误关联到本次事务。

选择一条记忆可以查看稳定 ID、版本、工作区、原始来源和修改记录。“保存修改”以用户当前确认的内容替换有效版本；“删除所选记忆”立即从有效集合移除，后续独立新会话不再召回。并发的旧版本操作会被拒绝，需要刷新核对。每个工作区最多 500 条有效/待确认记忆，单条最多 1000 字符。

来源区只展示已有记录，包含：

- 用户直接提供的原文、会话 ID 和本地动作 ID。
- 资料任务的会话 ID、运行 ID、原请求、实际来源的目标及读取状态、成果路径及回读状态、写入摘要与未知写入线索。
- 用户确认、更正、删除的审计，以及更正后的内容和对应会话。

`S1` 只是某次运行内的显示编号；跨运行身份使用 `session_id/run_id/S1`，来源表另有稳定 ID，且整个数据库绑定工作区。来源不会根据文件同名、相同 S1 或模型口头声称拼接。`verified` 只来自 R4 工具实际回读结果；保存事务关联不升级 `written`、失败或未知状态，也不证明文件目前仍与历史相同。

“查看来源会话”只恢复历史。来源面板不会打开文件、访问网页、执行工具或重新保存记忆。需要重新读取资料时，应在正常聊天中提出请求，仍走当前权限链。

## 召回、删除与兼容边界

每个前台请求都从当前工作区 SQLite 读取已确认内容，用规范化后的英文词与中文双字片段计算交集，过滤少量通用词；没有交集就不召回。匹配数量决定排序、稳定 ID 打破同分，桌面显示命中片段、版本和来源。首版不做语义同义词推断，例如只有“每星期的总结”而没有“周报”等相同片段时可能漏召回，也可能因共同片段误召回。

一次最多 5 条，内容、命中原因和来源引用的总注入长度最多 2400 字符（外围 system-reminder 标记另计）。超出预算的整条记忆不注入，不把关键内容截断成另一含义。数据库更正后实时参与下一请求；检索只看当前内容，不检索旧来源原文或审计。

调用链为 `ChatWindow/MemoryWindow → DesktopController → SessionService → WorkspaceMemory.recall → Agent.request_memory → 出站 api_conv → client.stream`。记忆只附在发给模型的副本，源会话不含这段注入，自动压缩和恢复附件也不能把它重新缓存；运行结束和新会话会清空请求字段。`memory_recall` 审计保留当时使用的版本，恢复时不会转成模型消息。

**删除不是抹除历史。**原会话中用户说过的话、模型当时的回答、工具证据和旧召回审计继续保留。若模型曾在回答里复述旧偏好，恢复那个旧会话仍可能看到那段历史；它不应被称为当前已确认记忆。需要验证更正/删除是否生效，使用独立新会话检查实际模型输入。

CLI/TUI 的自动过期清理会保留仍被待确认或已确认记忆引用的来源会话，以及这些记忆的更改审计所引用的会话。删除最后一条有效引用后，相关会话重新适用原有 30 天未活动清理规则；删除记忆本身不删除会话。清理只读查询已有记忆库，不为旧 CLI/TUI 工作区创建库；若库损坏、无法读取或属于其他工作区，则跳过本次自动清理并记录诊断。此保护不重建此前已丢失的会话日志，也不阻止用户明确删除会话。

桌面不再接通旧 Markdown 全文加载、模型选取和后台自动提取；`--memory` 保留为兼容参数，不能重新开启旧路径。不会自动迁移、删除 CLI/TUI 的旧记忆文件，CLI/TUI 原有记忆加载与提取行为保持。普通项目指令文件仍按 R4 前台行为读取；请不要把已经删除的记忆另写进 `LIKECC.md` 后期待其也被删除。

R5 定时任务始终使用单独 Runtime/SessionService，明确关闭两套记忆及个人信息提取，不加载前台历史。它只使用安排确认时的材料与输出快照；即使记忆中保存了默认输出路径，`ExecutionScope` 仍先拒绝范围外访问，范围内写入/网页再按已有规则确认。

## 本地存储

| 位置 | 用途 |
| --- | --- |
| `.likecc/memories.sqlite3` | 当前待确认/已确认记忆、不可变来源、修改审计；绑定解析后的工作区绝对路径 |
| `.likecc/sessions/*.jsonl` | 原会话及 `memory_action`、`memory_recall`、`run_evidence` 审计；这些审计类型不恢复成模型消息 |
| `.likecc/schedules.sqlite3` | 原任务定义、执行历史及核对时间；与前台记忆相互独立 |

使用标准库 sqlite3，无向量数据库或新增依赖。写入使用事务和版本检查。删除不自动回收记忆来源和修改审计表中的记录，这两类记录尚无自动过期清理；本地数据库未加密。复制记忆库到另一工作区会被拒绝。不要让 Windows 和 WSL 并发使用同一库。

以下流程全部使用 fake client；真实文件读写、权限卡片、SQLite 和会话服务保持。首次运行会打印一个**新临时根目录**，保留它用于退出重开。不要用普通 `--demo` 代替，此处需要持久工作区。启动器不读取真实配置、不创建真实 Provider client。

在原生 Windows PowerShell 中运行：

```powershell
Set-Location D:\ldj\03\DeskMate-Standalone
& C:\Users\28436\.conda\envs\deskmate-win\python.exe -s -X utf8 -m examples.deskmate_memories --review-fixture

R6-0 初始 A/B 是启动器明确标注的**合成历史**，其后的按钮重试是真实离线执行。2026-11-23 用户在 Windows 原生桌面逐项确认上述七项通过，Codex 对实际输入、SQLite 和成果文件进行了只读对照；结果见 [七项人工验收记录](verification.md#r6-七项离线人工验收2026-11-23)。这与 Qt offscreen 自动化是两组证据，仍不代表真实 Provider 质量或其他显示器配置通过。

```
