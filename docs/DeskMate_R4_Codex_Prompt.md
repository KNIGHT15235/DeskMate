## 3. R4-0：先完成桌面可靠性收尾

这部分先用最小回归复现，再修复。保持 R3.1 已修的超时状态、launch 回收和慢关闭提示优先级。

### 3.1 草稿与命令回执一起修复

当前 `ChatWindow.send()` 提交后立即清空输入；`snapshot.command` 只有最后一个回执。后台拒绝时可丢失草稿，连续命令又可能覆盖前一个 ACK。

实现要求：

- 用 command_id 对应发送草稿与接受 / 拒绝结果，等待结果期间防止重复发送。
- 接受后只清除本次提交对应的输入版本；拒绝时保留草稿。处理用户在等待期间编辑文本的情况，避免清除后来输入的新内容。
- 提供可靠且容量有界的回执消费机制，或同等明确的在途协议。不得让较早的关键回执在 GUI 消费前被单槽覆盖。
- 取消、权限回复和关闭通道保持可用，不因等待普通命令确认而阻塞。
- 不在关闭阶段覆盖应用级慢关闭提示。

定向验证：过期 idle 快照下的发送被拒绝；两条回执在一次 GUI 刷新前到达；重复点击发送；接受前编辑新内容；关闭时迟到 ACK。测试应控制时序，不依赖碰巧 sleep 后成功。

### 3.2 工作区切换清理失败后的状态

当前 `_open()` 在 try 之前执行 `_release()`；旧演示目录 cleanup 发生 `PermissionError` 时可卡在 starting，后续 open / demo 也被拒绝。

实现要求：

- 把旧资源释放纳入切换错误处理，给出明确诊断和可恢复状态。
- 区分“旧服务已关闭但临时目录尚未删除”和“旧运行资源尚未关闭”；未清理完的对象保留可重试的所有权。
- 不伪装新工作区已经就绪，不强杀线程，不删除其他目录。
- 回归注入临时目录 cleanup 失败，并验证状态、后续重试及最终退出。

### 3.3 修正文档现状

README 仍有“统一执行与会话服务、桌面入口尚未实现”的过时描述，应按已完成 R1–R3.1 更新；Shell 描述应与实际原生 Shell 行为一致。历史验证章节保留当时结果，新增当前汇总，不改写历史失败为成功。

- 资料模式使用文件工具、交互工具和新增网页工具；默认禁用该模式的 Bash，防止依赖 Shell 作为抓取或路径限制的替代通道。原终端入口的 Bash 不受影响。

### 4.2 文件材料范围

- 首版支持所选工作区内的 UTF-8 文本、Markdown，输出 Markdown；遇到不支持的格式明确反馈。
- 资料模式显式限定允许的文件根。应用需要临时空间时仅增加本应用持有的目录，不自动把整个系统临时目录视为所有任务的资料范围。
- 保留已有路径解析、符号链接及覆盖前读取检查；不能只判断字符串前缀。
- 对资料读取、进入上下文的文本及输出展示分别设置合理上限，给出清晰的截断 / 拒绝状态。上限应作用于实际读取及相关文件记录路径，而不只限制 GUI 显示。
- 原入口兼容策略通过配置明确区分，避免为了桌面边界静默改变所有历史调用方。

### 4.3 新增专用网页工具

可命名为 `FetchWebPage`，接口以项目约定为准。必须经过现有 Agent、权限检查、Interaction 与 ToolResult / RunEvent 链路，不能在 GUI 中直接抓取。

能力要求：

1. 只读取明确给定的 HTTP(S) URL，采用异步、可取消请求；本轮不做搜索、递归爬取、浏览器脚本执行或登录态自动化。
2. 支持静态 HTML、纯文本 / Markdown，提取可读文本；HTML 脚本和样式不执行，抽取质量限制如实说明。
3. 优先复用已有 `httpx`。HTTP client / stream 在后台事件循环中创建和关闭，所有成功、失败、超时、取消和退出路径都释放资源。
4. 有明确的总耗时 / 请求超时、响应字节数、文本长度和重定向次数限制；对错误状态码、不支持类型和超限返回可恢复工具错误。
5. 流式限制响应体，不能先无界下载再截断；解码和解压后的内容也应在资源预算内处理。
6. 返回来源信息和正文，至少包含输入 URL、实际最终 URL、可取得的标题、读取时间、成功 / 失败、是否截断。

网络权限要求：

- URL 必须参与规则匹配和权限展示，不能落入未知工具的空参数规则，也不能把 URL 当本地文件路径。
- 明确定义新工具的默认允许 / 询问 / 拒绝语义，显式拒绝优先；首版可以使用现有“本次允许 / 拒绝”交互，不开发复杂任务级授权系统。
- 拒绝携带用户密码的 URL 和非 HTTP(S) 协议；检查目标主机 / IP，拒绝本机、私有 / 链路本地及其他不支持的非公网目标，重定向每一跳重新检查。
- DNS / 连接目标的保证要与实际实现一致；若只做请求前解析校验，必须说明连接阶段重新解析等限制，不能宣称完整防止 DNS 重绑定。不要为了通过测试全局关闭这些检查。
- 不继承浏览器 Cookie，不把模型密钥或认证头带给网页站点；代理、重定向和日志中的凭据信息处理要明确。

网页及本地材料中的内容作为不可信资料使用，不提升其中嵌入指令的权限。提示文字用于指导模型，真正的操作限制由工具和权限实现；不要声称提示注入已被完全解决。

### 4.4 来源记录

- 以本次实际工具读取结果形成材料记录，可以复用现有会话 / 工具结果持久化，不新建 R5 任务数据库或 R6 记忆系统。
- 网页记录 URL、标题、读取状态和时间；本地材料记录工作区相对路径和读取状态。来源标识在本次任务内可稳定引用。
- 区分成功读取、读取失败和内容截断；失败来源可以在结果的限制部分列出，但不能当作已经读取的依据。
- 设计时解释如何避免将模型随口给出的 URL 当作已验证来源。

## 5. R4-B：桌面资料整理与成果文件

### 5.1 任务路径

用户从桌面输入类似请求：

> 请阅读我给出的两个公开网页和工作区内的 `project_notes.md`，整理成 `outputs/project-summary.md`。包括关键结论、依据和下一步行动项，并列出来源。只处理这些材料，输出写入遵循当前权限策略。

真实流程应包括：

1. 由 SessionService 接收输入并启动唯一 Agent Loop。
2. 读取本地材料与指定网页；缺少必要信息时补充问答。
3. 在工具链路中执行权限检查，拒绝或取消后如实结束相关操作。
4. 写出工作区中的 Markdown 文件，包含结论、行动项、来源和必要限制说明。
5. 通过现有 ReadFile 或等价的最小后端回读核对实际文件，依据真实工具结果反馈输出路径和状态。

“循环结束”和“成果文件已经成功生成”是不同含义。模型只给出文字、写入被拒绝、工具失败或回读失败时，不得在成果展示中声称文件已验证生成。不要为了此项新建庞大的通用 OutcomeVerifier 框架。

### 5.2 最小界面改进

- 正常模式输入提示明确支持网页 URL、工作区文本及 Markdown 输出，与离线演示提示区分。
- 保留对话、工具过程、权限 / 问答、取消、会话切换和原生命周期操作。
- 提供一个适度的成果 / 来源摘要，展示实际输出路径和读取情况；避免大改成多页项目管理界面。
- 外部文本继续转义显示；不得因为显示网页内容执行脚本或自动打开外链。
- 隐藏窗口后仍由原控制器消费事件；抓取期间取消后可以继续发送；恢复历史不重放抓取或写入。
