## R7-0：事件和通知入口

| 业务事件 | 触发位置 | 用户看到什么 | 能做什么 |
| --- | --- | --- | --- |
| 提醒到期，包括退出期间逾期 | `ScheduleStore.scan` 领取唯一 execution | 提醒到期通知、原任务中的待处理执行 | 查看该次、稍后提醒、关闭本条提示、取消本次或停止整个安排；在原入口完成提醒 |
| 等待本次模型调用确认 | `scan` / `DesktopController._start_scheduled` | 模型确认通知；尚无 run/request | 定位这次执行，明确允许本次模型调用，或取消这次/整个安排 |
| 运行中等待工具权限 | 唯一 `_consume → _event(PermissionRequest)` | 原权限卡片、以 run/request 区分的通知 | 继续处理回到原卡片，再本次允许/拒绝；通知本身没有批准能力 |
| 运行中等待补充回答 | 同一路径的 `UserInputRequest` | 原问答卡片及独立请求通知 | 定位原问题，明确填写并提交回答；超时后仅看历史 |
| 运行完成 | `_finish_scheduled` 保存最终证据和状态 | “运行结束”；只有对应 artifact 为 verified 才写“文件已回读核对” | 查看本次执行、具体成果路径和证据；无产物、写入拒绝、未回读分别说明 |
| 运行失败 | `ErrorEvent` / `_consume` 收尾 | 运行失败、原因、已有成果状态 | 进入原执行核对流程，核对后由用户明确发起新尝试 |
| 中断或未知写入 | `ScheduleStore.recover` 或 `_finish_scheduled` 检出 write_unverified | 中断待核对，可能已经发生写入 | 查看会话/成果/磁盘，沿用原核对再重试流程；通知点击不重放 |

原应用只对隐藏窗口的 pending request 发内存级“等待回复”气泡；最小化仍被 Qt 认为 `isVisible()`，所以漏提示。R7-0 先加入参数化回归，旧代码结果为 **最小化失败、隐藏通过**。现在旧路径已删除，所有业务气泡统一由持久通知领取后发送。判断为“隐藏或最小化”；主窗口正常可见时用通知中心和未读数。首次隐藏的说明留在窗口反馈，不另弹一个气泡。

## 持久化、去重与事实来源

沿用 `.likecc/schedules.sqlite3`，新增 `notifications`、`notification_requests`、`notification_meta`，不增加依赖、调度线程或运行事件消费者。SQLite 仍只由后台控制器持有；Qt 主线程只接快照、提交命令和显示托盘。

任务定义、execution 的状态及工具证据仍是业务事实。通知有自己的 `unread/viewed/snoozed/handled`，界面分别为未读/已查看/已延后/已关闭提醒。另有 `valid` 表示原事项是否仍成立。查看并不完成任务，关闭提醒并不拒绝/批准工具；源事项结束会使旧通知成为历史，保留其身份与查看状态。

定时通知携带 task_id、execution_id；运行请求再携带 session_id、run_id、request_id。前台原有权限/问答没有调度任务，使用 session/run/request 关联原会话，不伪造一个周期任务。模型确认没有 run/request，因此一个执行可留下“模型确认 + 权限一 + 权限二”三条独立记录。

去重键为 `execution:<execution_id>:<事件种类>` 或 `request:<run_id>:<request_id>`，数据库 UNIQUE 约束兜底。修改任务不改写旧 execution 快照；不同周期、重试和请求不共用通知。重复扫描、刷新和重开不追加同一事件。每次业务写入事务提交前重建投影，业务状态与通知一起提交；如果旧兼容写入方只更新了 execution，下次扫描/操作的幂等重建修正投影。测试注入提交前故障，验证业务状态和通知一起回滚。

首次升级把旧 completed/cancelled 作为已关闭提示的历史，仍保留提醒、失败及待核对事项，避免旧完成记录集中弹出。R5 恢复规则保持：原 queued/awaiting_model/running/waiting 重开成为 interrupted，权限请求成为历史，不能从通知恢复授权；退出期间新的到期由原 scan 领取，错过多个周周期仍只领取最近一次。

成果文案只读本次持久证据。`completed` 是 Agent 运行结束，可能被拒绝写入，也可能没有产物。新的写入拒绝从实际回复事实记录；旧版本没有该事实时，不根据一段模型回答猜测“拒绝”。`verified` 表示当时回读一致，不保证文件此刻没有被外部修改。未知写入和回读失败始终保留核对提示。

## 通知中心与操作含义

主窗口“通知中心”及托盘菜单均可进入。需要用户决定的有效事项优先，历史仍可查看。点一行或“继续处理 / 查看记录”会由后台重新核验工作区、通知版本、execution 和原请求，再定位任务窗口的具体执行及成果，或当前原权限/问答卡片。已结束的请求只进入历史；前台历史选中对应会话，可用原“恢复所选会话”查看。

进入仍有效的权限或问答时，会收起通知中心、任务窗口和记忆窗口，恢复主窗口并聚焦原卡片。附属窗口中的未保存草稿保留，可从原入口重新打开。允许模型后可以保留任务窗口打开；继续处理应直接露出权限卡片，不能停在遮挡它的任务窗口上。若请求已超时，则只能查看该次执行历史，不会重新出现可批准的旧卡片。

| 操作 | 实际影响 |
| --- | --- |
| 继续处理 / 查看记录 | 标记已查看并导航，不批准、不调用模型、不执行工具、不自动重试 |
| 稍后提醒 | 1 分钟至 7 天，只改变此通知的提示时间；不改任务到期、周期、模型授权或权限超时 |
| 关闭本条提醒 | 关闭这一条提示；任务和正在等待的请求保持原状，仍可明确取消本次或停止整个安排 |
| 取消本次执行（保留未来周期） | 包括待处理提醒在内，只取消选定 execution；活动运行核对同一 execution/request 后走原取消链 |
| 停止整个安排 / 周期 | 显式沿用 schedule_cancel：停用未来安排并取消当前活动执行；保留历史 |
| 完成这条提醒 | 位于原任务窗口，完成该次 reminder；之后该次通知不再提示 |

版本检查拒绝旧按钮、重复取消和切换工作区后的旧点击。权限 liveness 检查查询真实 Interaction Future，不能只相信上一次展示快照。即使点击之后卡片又超时，原 reply 仍按 session/run/request 再次核验。Windows 气泡点击不能可靠指出具体哪条通知，因此只打开通知中心供用户选择。

工作区切换刚开始、旧数据库尚未释放时，也拒绝旧通知命令。请求的首次事件到达、调度扫描及领取气泡前都会核验真实 Future；已结束的请求不会因迟到事件重新出现，也不会在结果事件尚未消费时继续提示。关闭通知只影响提示状态，不禁用仍有效事项的业务取消按钮；上一周期的取消点击不能取消下一周期。

原权限/问答卡片提交时，先验证请求和回答格式、持久保存决定，再放行等待中的请求。若保存失败，卡片继续等待，工具不会执行，用户可明确重试；保存并放行后的纯展示刷新失败只报告刷新问题，不把已接受的决定说成拒绝。重启仍不会根据已保存的允许记录恢复或重放工具。

若运行收尾时无法保存请求结束事实，控制器显示收尾错误并停止后续领取，清空过期卡片；核对后可明确重新打开工作区。不会卡在“取消中”，也不会把未保存的收尾伪装成成功；重开仍按原中断核对规则处理。

## 免打扰与气泡约束

通知中心可保存启用状态、HH:MM 开始/结束和 Asia/Shanghai/UTC 时区，设置按工作区持久化。默认未启用；22:00–08:00 支持跨午夜，起点包含、终点不包含；起止相同表示全天静音。

静音不影响任务执行或通知入库。解除静音、延后到期时，只领取仍有效且尚未处理的通知。积压一次合并成一个提示；一个工作区气泡至少间隔 30 秒。权限或问答可能在延后时间到达前超时，此时只保留历史，不再提示。正常可见窗口不弹业务气泡；无托盘仍可在窗口走完整流程。

气泡领取遇到临时数据库错误时，后台返回失败回执，界面至少等待一秒再尝试。失败事务不消耗提示代次；不会因为一次失败就永远停发后续提示。

气泡的“已领取代次”先持久化，再由 Qt 显示。这样重复轮询/重启不会重发同一代；显示前还会过滤刚结束、再次延后或进入静音的事项。数据库提交与 Windows 系统通知无法组成原子事务：若领取后进程崩溃、窗口已恢复或系统阻止显示，可能少一个气泡，但通知中心记录仍在。这是**可持久查看、每代最多领取一次**，不是保证操作系统恰好显示一次。

不提供进程完全退出时的系统后台唤醒。数据库和请求历史未加密，尚无自动归档/清理；大量长期历史的性能仍待持续观察。原本地单工作区调度锁保持，Windows/WSL 不共写同一工作区。

## 可直接复制的离线演示命令

原生 Windows PowerShell，使用已有 deskmate-win 环境：

```powershell
Set-Location D:\ldj\03\DeskMate-Standalone
Remove-Item Env:QT_QPA_PLATFORM -ErrorAction SilentlyContinue
& C:\Users\28436\.conda\envs\deskmate-win\python.exe -s -B -X utf8 -m examples.deskmate_notifications
```

启动器打印新临时根目录并保留 A/B 两个工作区。Provider 必须为 `offline-r7 / fake`。它不读取真实配置、不创建真实 Provider client。首次建立五个未来安排：一次性提醒、两次写入、拒绝写入、模型失败、未知写入，依次在 1–5 分钟到期。所有资料任务的模型策略均为每次确认。失败场景及 `outputs/unknown.md` 的部分写入是明确的离线故障注入，其他文件仍走实际本地工具。

保存打印的根目录，在另一个 PowerShell 中设置以下变量，可随时推进演示时钟；不改 Windows 系统时间，也不启动第二个桌面实例：

```powershell
Set-Location D:\ldj\03\DeskMate-Standalone
$R7Root = '<替换成启动器打印的根目录>'
& C:\Users\28436\.conda\envs\deskmate-win\python.exe -s -B -X utf8 -m examples.deskmate_notifications --root $R7Root --advance-minutes 10
```

真正退出后重开同一根目录：

```powershell
& C:\Users\28436\.conda\envs\deskmate-win\python.exe -s -B -X utf8 -m examples.deskmate_notifications --root $R7Root
```

推进时钟只用于调度/免打扰/稍后提醒。权限卡片默认五分钟真实等待超时，不因演示时钟偏移而扩大授权。不要在旧实例仍运行时执行重开命令。若在模型待确认期间重启，按 R5 规则会转为中断：核对后在原入口明确发起新尝试，再允许模型。

WSL 可见离线启动（WSLg 的实际显示需另行人工观察）：

```bash
cd /mnt/d/ldj/03/DeskMate-Standalone
env -u QT_QPA_PLATFORM /home/ldj/anaconda3/envs/cc/bin/python -s -B -X utf8 -m examples.deskmate_notifications
```

`--check` 只准备工作区和未来安排并打印路径；`--help` 查看参数。`model-inputs.jsonl` 记录 fake client 的实际输入；`writes.jsonl` 记录样例工作区内每次到达真实写入边界的调用。拒绝写入不会增加对应写入边界记录。临时数据保留供复核，不写入用户现有工作区。

## Windows 一次走完的可见验收清单

以下七条人工主流程已于 2026-11-23—24 完成，实际反馈和逐步只读对照见[验证记录](verification.md)。**offscreen/FakeTray 的结果与 Windows 屏幕观察分别记录**：真实无托盘、多屏/缩放组合及每次权限气泡均可见等没有逐项人工覆盖；旧工作区过时点击拒绝由自动化验证。复验时建议关闭其他 DeskMate 实例，在同一个新根目录走完，不在每一步创建新根目录。按需推进时钟到所有样例到期，再按名称选对应执行。

| --- | --- | --- | --- |
| 1 启动与入口 | 核对 offline-r7 / fake、A 工作区和五个安排。打开通知中心，检查滚动、按钮与长文本复制 | 正常 DesktopApplication、Qt 控件、隔离假模型及实际存储 | Windows 可见布局、缩放、按钮可达 |

| 7 工作区隔离、历史与重开 | 空闲时切到 B，确认没有 A 的事项，再切回 A。查看完成、拒绝、失败、未知历史并恢复对应会话；停止剩余周期，真正退出再重开，比较调用日志和文件时间。无托盘环境通过主窗口通知中心走流程 | 旧 A 通知五种点击命令在 B 全部拒绝；模拟无托盘全流程；历史恢复和重启无新增模型调用/写入，旧授权不复活 | 切换后的界面没有旧卡片；Windows 正常退出、重开和托盘生命周期。本机无托盘场景若无法提供，记“仅自动化” |
